# Awesome — Brand Context for SEO

> Read every time. This file is read by every phase of the SEO sprint.

## Product

- **Name:** Awesome
- **One-liner (≤20 words):** Search and compare GitHub repositories recommended across curated awesome lists.
- **What we do:** Awesome indexes repositories from curated GitHub awesome lists, enriches them with current project metadata, and makes them searchable by relevance, stack, freshness, health, growth, and cross-list recommendation signals.
- **Pricing structure:** The discovery product is free. Revenue surfaces are clearly labeled sponsor and highlighted-repository placements, plus an optional remove-ads purchase.
- **Free tier?** Yes — repository and awesome-list discovery are available without payment.

## Audience

- **Primary persona:** Developers evaluating open-source projects.
- **Secondary personas:** Open-source maintainers, engineering leads, technical researchers, founders, and AI agents.
- **Industries we target:** Software development and technical research across industries.
- **Company size we target:** Individuals through technical teams.
- **Jobs to be done (top 3):**
  1. Find maintained repositories that solve a technical problem.
  2. Compare project health, momentum, stack, and curator recommendations.
  3. Monitor repository development without repeatedly checking GitHub.

## Brand voice

- **Voice tags:** Clear, trustworthy, practical, technical, calm, direct.
- **Person/perspective:** You-focused product voice; use “we” only for product commitments.
- **Forbidden words/phrases:** revolutionary, game-changing, seamless, ultimate, guaranteed, unbiased.
- **Reference brands for tone:** GitHub documentation, Linear documentation, and the existing Awesome product copy.

## Anti-positioning

1. Awesome is not a Git hosting or code-search replacement.
2. Awesome does not treat stars alone as proof that a project is healthy.
3. Awesome does not sell rankings disguised as editorial recommendations.
4. Awesome does not claim every indexed repository is safe, maintained, or production-ready.
5. Awesome is not a package registry, vulnerability scanner, or license-compliance system.
6. Awesome does not require an account for public catalog discovery.

## Concrete differentiators

1. Cross-list recommendation signals show how often independent curators include a repository.
2. Current star growth, commit activity, freshness, stack, and archive signals make static lists comparable.
3. Repository updates, RSS/email monitoring, API access, and a public read-only MCP turn discovery into an ongoing workflow.
4. Users can search one catalog across many awesome lists and request missing lists.
